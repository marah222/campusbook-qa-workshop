# CampusBook — Student QA mission

The university wants an easy way to find and reserve study rooms, prevent booking problems, and manage existing reservations. The development team says the application is ready. Your job is to gather evidence and recommend whether the university should release it.

## Today you own one story
Write a user story from your objective, two observable acceptance criteria, and one unanswered question. Create a GitHub Issue. Do not assume current application behavior is correct.

## GitHub flow
Paper story → Issue in Project → manual test evidence → personal test contribution → team branch → one draft PR per team → peer + optional AI review → CI evidence → release recommendation.

## AI policy
- Paper-based stories, acceptance criteria, initial test design, exploratory observations and final release vote: **no AI**.
- Unit/API/UI coding: AI may explain syntax or debugging *after* your own test design; disclose material assistance.
- Maintainability and code review: AI is a second reviewer; human verifies suggestions and remains responsible for approval.
